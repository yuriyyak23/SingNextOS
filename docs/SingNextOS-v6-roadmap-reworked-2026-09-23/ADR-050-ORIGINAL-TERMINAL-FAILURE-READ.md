# ADR-050: Read original terminal failure after Start publication

Accepted for implementation, 2026-10-11. Actual Start consumes typed terminal status before publication (ADR-049), so its failed invocation is already Faulted. ObserveVirtualTrap may expose that same surviving original failure through a pure query without re-opening execution or delivering/acknowledging a native event.

VDA retains kind and exact source revision atomically with its own terminal state publication. Canonical original owner, published authority, non-exhausted unchanged revision, and a known non-Completed kind are mandatory. A copied owner, arbitrary Faulted projection, missing marker or ABA cannot substitute for that publication. CapabilityAuthority still admits current Read on the exact Traps resource; process incarnation and composed/ancestor sources are rechecked before final response commit. The query does not grant permission or resume a completed lifetime.

The bridge retains original Start's own child publication revision and captured ancestor revisions. Its reader rejects independent history/ABA even when current state tuples compare equal. Queried kind/receipt must agree with the previously admitted original terminal result. Native/SDK/provider canonical original lookup/current validation remains mandatory; missing/malformed/lost response does not imply containment. Raw is retained before subsequent callbacks; final response rechecks local/source revisions under existing owner commits. Repeated exact observation repeats only the pure query, never CPU execution, state publication or delivery effect.

Terminal reads leave native pages, Region and all quantitative charges unchanged. Independent exact artifact no-further-use, guest/child/root closure and mailbox containment remain separate consumers. Source/history/copy faults retain their existing cleanup pins; pure reply loss is not a new native invocation and cannot erase an independently proven original backing closure. Legacy Running trap behavior remains unchanged; Completed has no failure trap.

No new ledger, release authority, capability, permission or machine semantic. External Contracts1.34.0/Runtime1.23.8 unchanged; actual local VDA/bridge/kernel callers consume this seam. Evidence in [consumer record](../../artifacts/v6/iteration-20261011-terminal-failure-read/report.md). Overall runtime remains Partial/Open. Gates OFF; ProductionQualified false; Java-only skipped; ISA NONE.

Implementation refinement: preserve the first provider/bridge original terminal raw across failed pure reads. Kernel retains an already Faulted publication only while its same authoritative local owner/revision remains current; every retry repeats fresh authorization/source/history checks. This permits lost/malformed pure reply retry without repeating execution, removing backing pins or reviving active permission.
