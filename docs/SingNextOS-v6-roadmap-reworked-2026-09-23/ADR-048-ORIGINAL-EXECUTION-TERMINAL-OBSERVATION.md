# ADR-048: Original external execution terminal observation

Accepted for implementation, 2026-10-11. Actual CPU-backed Start already retains exact terminal retired-work evidence, but generic ExecutionFault and caller-supplied legacy ReportChildTrap cannot refine that evidence into a machine MemoryFault/IllegalInstruction.

The external runtime consumes the existing typed runner status without modifying machine encoding, legality, memory, retire or reset semantics. On the existing original Start fact it retains the same Start request, the same terminal execution receipt, and an external boundary kind: Completed, BudgetExhausted, KernelRejected, or ExecutionFailure. Unreceipted/unsupported/unknown outcomes have no typed observation. ExecutionFailure is explicitly not MemoryFault or IllegalInstruction.

An additive optional pure lookup interface resolves this surviving original fact. Equal/copy request, substituted receipt, missing canonical factory/history, or unknown enum cannot produce it. The SDK retains raw before source callbacks and translates only the same original native request/receipt under the current original artifact/child/mapping and manifest sources. The platform provider retains its raw observation and checks the original published Start and current owners before returning typed evidence. Package adoption is required; sibling edits do not update consumer assets.

Kernel ObserveVirtualTrap uses this additive producer route for execution-boundary kinds. Fresh process/capability/domain lineage, canonical artifact/child/guest/parent/root owners, source/revision and pending dependency interlocks surround lookup and final publication. Lookup and provider/source callbacks run outside owner commit locks. Final publication of a non-completed terminal failure commits VDA Running→Faulted, refusing resume and subsequent active delivery. Completed execution produces no failure trap. Legacy trap providers retain their previous semantics.

This is a pure query of an existing completed invocation, not a new native trap delivery/acknowledgement effect, and not a machine trap decoder. Same-original reconciliation may repeat the pure query without repeating CPU execution. A missing response conveys no closure or containment. Failed trap publication does not erase the original Start/backing fact. Cleanup still requires the independent exact original artifact no-further-use/guest/child/root closure consumers; trap kind, IsTerminal and absence of an object do not release memory or charge. Independent events/history/backing users remain governed by their existing owners and pins.

Native current-original validation runs after source callbacks: surviving raw identity alone does not authorize publication after factory/history loss. Independent mailbox/backing users require their own containment and can retain Region/Owned charge after artifact/guest retirement.

No new ledger, recovery authority, permission, transaction manager or release owner. B1 cold continuation and general B2/B3/all-fact-loss remain open. Native physical trap decoding and stateful resume remain separate contracts.
