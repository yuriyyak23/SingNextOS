# ADR-031 — Original runtime DMA copy backing lifetime

Accepted for additive managed backing consumer, 2026-10-11; gates OFF, ISA NONE.

The actual ExecuteV6ProviderDmaDataMotion caller retained grant/cycle lifecycle but did not reserve OwnedBuffer storage. Provider effect could overlap CPU access or local transfer, and late destination loss during source-release callbacks could return a stale output. An executing DMA provider therefore needs a runtime-owned byte reservation in addition to V5 grant admission; metadata is not backing authority.

Add IPlatformDmaCopyBackingProvider and an opaque reference to reserved source read bytes/destination write bytes. RuntimeBufferLease remains the storage reservation owner, RegionAuthority owns use/reclaim, bridge/provider own original grant/cycle/effect facts. A payload correlation retains exact buffer references, process handles, grants and prepares; it is not another admission/completion ledger. Reserve capacity and storage before provider effect; retain possible effect before invocation, outside commit locks. Same-original retry retains the same bytes; overlap/reentry refuses. Existing V5 metadata submission remains available. Actual byte movement requires the additive producer capability; absent capability refuses before invocation.

Exact NotAccepted with current source continuity consumes no-effect and releases reservations. Any unknown/malformed/lost response retains reservations with existing bridge pins. Both completions, post-completion visibility and both original mapping closures end the provider byte lifetime. Disposal invalidates future Memory.Span access even if the provider retained the Memory object. Source release and destination publication remain separate: after callbacks, publication revalidates the original process, Region and buffer under the existing kernel gate. Independent faults are not cleared by storage disposal. Byte views use the existing storage without a second full-buffer staging allocation; managed views expose no native pointer/pinning support.

This contract does not supply an executing HybridCPU DMA producer, physical DMA containment, durable all-fact-loss recovery or shared atomic access. Those remain separate producers/contracts. Developer checks exercise the actual RuntimeKernel movement and quantitative charges using a bounded test provider; this is runtime consumer evidence, not a production provider claim. No package/schema/ISA changes or capability resurrection.
