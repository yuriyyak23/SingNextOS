# ADR-019 — Adapter-created external parent root closure

Accepted 2026-10-10 for the actual executable child → guest/child closure →
RuntimeKernel.TerminateProcess consumer. The external-parent-root-close repro
retained a Ready external parent and its Context/RootAuthority/Binding after local
Region/budget reclaim. The adapter-created parent is a separate original lifetime
from the neutral root; its closure must precede provider root publication/reclaim.

An optional additive V1 original-domain Close addresses the same native Bind
receipt and immutable operation before effect. Existing native domain owner
checks canonical identity, source and same-owner child inventory under its gate,
retains intent/raw outcome, and closes only its captured backend owner. Callbacks
remain outside unrelated commit locks. Exact terminal closure ends native root
context and future use; pre-effect refusal is distinct no-effect. Unknown/lost
history never repeats Close. Pure lookup returns the canonical surviving original
envelope; equal copies/foreign receipts and absence cannot transfer closure.

The adapter parent registry becomes a stable original lifetime record retaining
Bind/request/Close facts. Provider root teardown consumes this exact external
parent closure after known neutral root closure, before final local publication.
Late source/owner loss retains outcomes for lawful same-original cleanup without
repeated effects or fresh active execution permission. Independent backing users,
unknown parent admission and incapable external closure keep pins. Native and
adapter dependent inventories refer to original owners, not equal lease copies.

The composed root intent stages the external-parent request before neutral Close.
Pure ResolveDomainClosure remains effect-free. An optional explicit continuation
finishes only a never-invoked staged parent component, or a freshly admitted
component after exact no-effect consumption; an invoked/unknown component uses
pure original lookup. It never repeats neutral or external Close. The existing
bridge cleanup consumer selects this continuation on the same retained original
root owner, with fresh applicable sources and balanced interlocks. Partial
closure is never reported as overall no-effect or reclaim permission.

No new authority/ledger, enum/V2/schema, ISA or core architecture change. Existing
operation correlation and local authorities remain owners. Packages require
actual adoption/consumer verification. Gates OFF; bounded single-host executable
dev claim only. General B2 unknown/all-fact-loss, B1 durable recovery, physical and
ProductionQualified properties remain separate.
