# ADR-039: Original external child software event mailbox

Accepted for implementation, 2026-10-11. Consumer: RuntimeKernel.InjectVirtualEvent and its existing KernelEventRegistry staged publication; executable provider/SDK currently lack a producing route. This is an external software relay, not machine IRQ/retire/firmware semantics. Timer/Preemption remain unsupported until their independent executable contracts exist. ISA NONE.

The existing native child owner retains original admission/request and its already captured immutable semantic-source datum before possible delivery; it does not materialize a second private byte buffer. Root/child canonical factories, lineage, source version/generation, authority and admission are checked under parent→child gates with the mailbox effect. Original request and sequence/operation latch prevent retry admission. Explicit refusal has NoEffect and NoFurtherDelivery; missing record/response does not. The mailbox supports Created/Running/Parked software relay independently of the legacy machine-facing event API; legacy V1 semantics are unchanged.

Consume clears the exact private mailbox under its sole owner and retains original terminal delivery evidence. Containment can clear retained admission intent without an admission reply, but cannot infer no-effect. Original pure lookup returns retained objects only after current canonical/history validation. Child closure is denied while mailbox or issued history is unresolved. Completed same-original settlement needs no new active permission or operation identity.

SDK captures original request before producer invocation, retains raw before queries/callbacks, checks exact original object and fresh source/revision before publication, and preserves unknown effects for cleanup. A possibly invoked Consume/Contain is not repeated after lost reply: pure reconciliation only. Provider and bridge must adopt the same-original protocol before the kernel route is considered closed. KernelEventRegistry endpoint/publication/signal users remain independently owned; native NoFurtherDelivery cannot remove those pins or authorize publication.

Actual adoption uses Contracts1.30.0 / Runtime1.22.2 with unchanged operationSchema1.4.0 / manifestContract1.3. Original SDK/provider/bridge callers consume the same scoped facts; BeginDrain performs event cleanup before its independent provider transition. Unknown Consume can use the separate admission-based containment fence without repeating Consume; late Consume cannot deliver after that fence.

The bridge records its admitted local child state/revision before invocation. Exact event closure can continue only the synthetic fault produced by that invocation at the same surviving revision, with cleanup-only state. This does not restore native lifecycle, capability permission or effect admission. Independent lifecycle mutation/ABA/exhaustion remains pinned. V1 known-delivery teardown is preserved; unknown/malformed V1 delivery cannot gain the new optional guarantee.

Bounded exit still requires final affected/native and applicable main terminal verification in the implementation record. Gates OFF; ProductionQualified false; Java-only skipped. Cold continuation, all-fact-loss, public hardware delivery and independent users are outside this bounded software contract.
