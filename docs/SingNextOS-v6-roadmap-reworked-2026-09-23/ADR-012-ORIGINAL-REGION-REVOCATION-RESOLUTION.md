# ADR-012 — Original region Begin response resolution

Accepted for surviving-original managed region-revocation consumer, 2026-10-10; gates OFF. This is not an unknown underlying-invocation containment or durable recovery contract.

Actual producers: RuntimeKernel.RevokePlatformRegionMapping, process teardown and model-domain drain call bridge BeginRegionMappingRevocation. HybridCPU reserves its operation internally, calls exact original mapping Close, and publishes ticket only after known closure. Lost Begin response leaves bridge Faulted without an operation identity even when the provider retained exact Closed. ObserveCompletion(operation) cannot address that case. Repeating Begin or Close is not resolution.

Add optional IPlatformRegionRevocationResolutionProvider, preserving existing V1 methods. Its Begin accepts an invocation-local request key plus full original mapping/policy. The bridge allocates and retains this request before possible effect; the provider attaches the same request to the existing original mapping owner before Close. The key is correlation, never permission or closure. A second request cannot replace the original invocation. Empty key, unsupported policy, mismatched request, missing/foreign owner and unknown outcome deny.

Resolve accepts the exact original request and returns that request plus its original ticket only when surviving same owner retains exact underlying Closed/Revoked. It must not invoke Close/Begin, allocate a replacement operation, import another object's receipt, or infer closure from NotFound/terminal/absence. Original parent/source and dependent lifetime continuity remain required. Provider keeps the prepared operation with its existing mapping owner; resolution may publish only the already proven closure. Absent routing may be read from the same original owner; a foreign route refuses. Unknown underlying Close stays pinned because resolved neutral contracts do not establish exact unknown containment.

Bridge retains initial raw Begin outcome and separate raw resolution. It validates exact request equality, full ticket identity, same owner and fresh provider/backend source before adopting operation; final existing completion/Region/budget consumers remain authoritative. Resolution failure/throw/source loss preserves fact, charge and pins; successful receipt retained after late refusal permits bounded retry without a new effect. Overlap is serialized by existing closure interlock; callbacks remain outside locks. Exact consumed closure does not require fresh active permission or repeat resolution.

Required evidence: lost Begin reply after exact closure, wrong request/mapping/generation, absent/foreign original route, unknown underlying outcome, source callback loss/reentry/throw, overlap, no repeated Begin/Close, exact local receipt consumption and actual Region/quantitative reclaim. Actual HybridCPU provider must be checked in addition to model kernel consequence tests. One applicable broad after coherent source changes. No package/ISA changes; Java skipped; Boot/Samples excluded.

Durable storage/reboot producer remains B1; underlying unknown containment remains B2; executable artifact release remains B3. GUID uniqueness alone proves neither durable freshness nor original owner recovery. No new authority/ledger and no production/durability/general atomicity claim.
