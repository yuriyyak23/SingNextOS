# ADR-011 — Verified original no-effect journal projection

Accepted for the bounded managed resource-recovery consumer, 2026-10-06; gates OFF.

A PossibleSubmit journal frame records intent before the actual operation submit/provider callback. A lost append acknowledgement can leave that frame present while the original operation remains unsubmitted and its budget/resource owners commit pre-submit cancellation. Raw PossibleSubmit→CancelledPreSubmit remains forbidden: cancellation alone cannot undo an unknown effect.

The existing kernel journal writer may project existing SettledContained with empty charge only after fresh exact original owner checks: operation handle/generation from correlation, Cancelled disposition, NotCrossed boundary, no submitted binding, Prepared/Admitted/Released state; resource binding exact operation/budget owner/lease/envelope and CancelledPreSubmit; budget exact owner/generation, ExternalEffect lifetime, original reserved amounts, CancelledPreSubmit and empty charge. The signed original journal tuple must also match. These terminal owner facts cannot acquire a new effect after validation. Any mismatch retains conservative recovery/pins. Only PossibleSubmit or an already matching projected SettledContained record takes this path; generic quarantine is not reinterpreted.

SettledContained here records a bounded no-effect recovery fact stronger than mere cancellation. Warm budget/resource states remain CancelledPreSubmit; no ResourceSettled, provider closure, publication or physical containment fact is invented. The existing cold recovery consumer already accepts this zero-charge terminal record. Exact retry is idempotent; the raw journal transition validator and authenticated encoding remain unchanged. No new enum, public API, schema, package, authority or ISA change. Existing V1 readers understand the record. Original provider effects/unknown outcomes require their own closure contract and are excluded.

Tests retain raw cancellation refusal and signed source/unknown/version/HMAC/torn-tail checks; actual warm kernel/file-journal tests distinguish pre-effect cleanup from a concurrently submitted original owner. This is managed RuntimeEnforced recovery, not physical durability or ProductionQualified evidence. Java-only checks skipped; ISA NONE.
