# ADR-030 — Original native IRQ producing fence

Accepted additive local ModelOnly producer/consumer, 2026-10-11; gates OFF, ISA NONE.

Actual RuntimeKernel.TerminateProcess terminal repro closes a foreign equal-numeric IRQ binding. Existing native device owns original Bind intent before effect; admitted IRQ captures that exact device/root admission factory. Existing IRQ owns Close request/raw. Realm, request, canonical owner, factory and parent lifetime are checked under native lifecycle lock atomically with effect. Pure surviving-original lookup never effects and missing/history loss never implies closure or no-effect. Exact no-effect is separate from Closed; pending delivery retains V1 refusal.

Provider retains original raw before source callbacks, uses same original request for pure cleanup after reply loss, and never repeats an unknown invocation. Bridge consumes optional exact no-effect without synthesizing closure. IRQ delivery, endpoint release and original route inventory remain independent requirements of this consumer and need terminal consumer verification before bounded closure. No new authority/ledger, public enum/V2/schema/package/machine changes. Native project references are actual adoption. Production/physical/durable/general unknown containment remain open.

Producing need: a lost Poll/Complete reply in the actual kernel delivery caller can leave a pending native delivery. V1 Close still refuses it. Additive original containment retires the exact native IRQ lifetime under the same lifecycle lock, including its pending delivery, and prevents every subsequent native signal/poll/completion. Its own request is retained before effect and its exact receipt survives for pure cleanup-only retry. Realm, canonical IRQ/device/root owners, admission factories and intact issued-count histories are mandatory. Missing/history loss/foreign facts do not produce containment. This is a local ModelOnly producer guarantee, not a physical/provider-wide guarantee or reboot recovery.

Actual provider callers adopt original Poll/Complete, retain raw before source callbacks and use pure same-request lookup after reply loss. Native source revision is checked before delivery publication; equal writes/ABA and exhaustion deny. An opaque platform Bind request reaches the native intent; the bridge stores it at the existing device before possible effect. Pure Bind resolution can adopt a cleanup-only IRQ owner or consume exact no-effect; it cannot publish new permission. Canonical IRQ inventories retain the authoritative records through routing loss.

Bridge delivery-invocation uncertainty is separate from independent source/endpoint/local-publication faults. Only the former may invoke native containment. Endpoint reservation release still commits at KernelEventRegistry against the same original reservation/source; process/device/root closure and Region/budget consumption remain separate. Exact native containment does not settle independent local event, signal, backing or history users. Incapable providers remain pinned with no repeat. Completed consumed lifetimes require no fresh active permission and are excluded from active cleanup inventories.

Final native/provider/affected/main verification and bounded record are required on the coherent source tuple; see the current report in artifacts/v6/iteration-20261011-native-original-irq-fence. No enum/V2/schema/NuGet/ISA delta; additive local Contracts/AuthorityCore/Model references are actual adoption. Gates OFF, ProductionQualified false.
