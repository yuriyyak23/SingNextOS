# ADR-014 — Original native realm and revocation NotAccepted

Accepted for actual optional ModelOnly native root/mapping producer, 2026-10-10; gates OFF. Existing runtime incarnation from ADR-013 is source correlation, never permission. A new native facade can reproduce numeric root/mapping lease tuples; it cannot replace the original provider lifetime. Capture the optional incarnation at provider construction and check it before root Bind, owned mapping admission and original cleanup, and after callbacks before publication. Original Close requests carry that original incarnation, not whichever realm is currently reachable.

Actual kernel repro accepted foreign equal-tuple Bind/Close/root cleanup; the initial Map fixture was invalid and corrected before final verification. A native source exception before Close also caused a permanent unknown pin despite no native invocation. Optional IPlatformRegionRevocationNoEffectProvider and IPlatformDomainRevocationNoEffectProvider explicitly guarantee that NotAccepted on their Begin/Revoke methods proves zero effect of that invocation, with a default ticket. The HybridCpu producer opts in and returns this evidence only before a native effect-capable call. V1 providers do not acquire this guarantee from the status alone: existing consumers demonstrate a NotAccepted response after operation creation. Their original facts remain pinned/no-repeat. This is not a generic Denied/Faulted interpretation, NotFound evidence, completion or release.

Bridge retains the original response and consumes this no-effect invocation only at the same authoritative owner with fresh source/epoch checks. Mapping remains active, charge/backing remain owned; a later Begin needs fresh admission and a new invocation. Root permission remains quarantined after cleanup refusal; a later cleanup may retry only after exact no-effect fact consumption. Late source/owner loss retains the response until exact local consumption; generic/unknown outcomes remain pinned/no-repeat. Malformed NotAccepted with a ticket is not no-effect evidence.

Raw native results must be retained before source callbacks. Known completed lifetime needs no new active admission; completed consumption must not re-pin. General cross-owner concurrent atomicity, APIs without native incarnation fencing, durable first-snapshot freshness, all-fact-loss/reboot lifetime continuation, production containment and artifact release remain separate gaps. This does not create a recovery authority, durable schema, public enum/V2, native ISA change or new ledger.

Verification: actual RuntimeKernel with equal-tuple replacement native realm and source exception, zero native calls before refusal, retained charges/backing, same original realm restoration with exact cleanup/reclaim, no-effect response late owner/source loss and malformed/generic negatives; affected Platform/Virtualization and one main broad. Existing optional contract uses local project references, no sibling NuGet adoption.
