# ADR-032 — Original native managed DMA copy

Accepted for bounded local managed byte producer and actual HybridCpu caller, 2026-10-11; gates OFF, ISA NONE.

ADR-031 supplies actual RuntimeKernel movement storage reservations. The missing producer must independently admit both original grants/prepared cycles and bind one original invocation before possible byte effect. Add an opaque native request containing original realm, grant admission factories, original prepare requests/cycles and reserved byte views. Existing source grant owns the copy fact; destination holds a reference to that same fact. Issued-count/self histories and canonical grant/root/device/mapping factories deny history loss, copies and equal foreign realms. Native lifecycle gate serializes current admission with Span.CopyTo; no memory-manager callback runs inside it. A narrow PendingCopy interlock prevents grant Close or cycle mutation during view acquisition; it is not permission. Fresh source/cycle validation follows callbacks before effect.

Copy is synchronous managed byte execution, not machine DMA/opcode execution. Completed and NoFurtherByteUseGuaranteed are explicit produced facts. Pure same-original lookup never copies bytes and survives legitimate later acquire/grant closure; separate current validation protects admission publication. Missing/foreign/history loss is unknown, not no-effect. Retained raw and factory identity precede source callbacks. Producer byte references are dropped once the synchronous lifetime ends, while immutable identity/history remains; runtime storage reservation consumption stays independent. Copy and malformed/no-effect observations cannot substitute for independent completion, visibility, Region or quantitative closure.

HybridCpu provider adopts the original producer with existing grant/cycle owners. It retains native invocation/raw before callbacks, resolves lost replies purely, validates fresh native and provider sources before publication, and emits exact two-leg completion evidence through the existing kernel completion/visibility caller. Additive platform original copy request lets the bridge retain invocation before effect and reconcile a lost response without a second effect. Incapable, unknown query, independent source/history and malformed paths remain pinned. V5 metadata submission remains available; this provider refuses unbound single-leg/metadata copy effects. Advertised DMA contract becomes V5 only with the actual optional native producer; availability remains RuntimeAdmission, with no executable/production gate promotion.

This does not establish physical IOMMU/DMA containment, durable reboot/all-fact-loss continuation, shared atomic coherence or core HybridCPU-v2 ISA semantics. B1 trusted storage freshness/authenticated continuation remains a separate prerequisite. No package/schema/opcode changes; new native APIs are consumed via local Contracts/AuthorityCore/Model project references.

Provider incarnation is allocated once for the in-process provider inventory; exhaustion refuses a new instance. It is independent of native realm continuity, not a durable cold-restart identity. A temporary absent/foreign native source must not become a permanent provider reset for unrelated already admitted cleanup. Typed producers validate native realm themselves. Unpublished pure copy reconciliation requires current prepared native and canonical local cycles before it can publish a receipt. Already published completed lookup survives legal parent/grant closure without fresh active permission. A retained malformed raw cannot be replaced by a later equal/corrected query. NoFurtherByteUseGuaranteed covers only this synchronous original producer invocation; independent backing users and generic unknown/history pins are not consumed by that observation.

The actual process/device teardown after copy reply plus query loss produces a cleanup-only need. Add IPlatformOriginalDmaCopyLifetimeProvider: same opaque invocation, surviving exact native raw/factory history and explicit NoFurtherByteUseGuaranteed, with no completion/publication receipt. Fresh native realm and canonical provider source/cycle records are validated before consumption; a legitimate later native acquire is not another active admission. The bridge retains one shared original invocation in both grant histories before effect, issued counts/self identity, captured source revisions/canonical cycles/backend epoch and a separate uncertainty bit. Pure lifetime resolution may consume only an unpublished invocation's uncertainty. Independent submission pins, accepted active submissions, foreign/malformed/absent/history loss and source/canonical drift cannot be discharged by it. Callbacks run outside commit locks; cleanup interlock is balanced. Once consumed, the same copy lifetime needs no new active permission; subsequent grant Close independently validates its original sources and can retry its own lost response. Runtime backing reservations end only when both exact original grant closures are consumed; existing mapping/process teardown then decides Region and quantitative release. A failed first leg with a legally closed second leg retains payload reservations and charge until retry. This does not establish unknown accepted-pair/publication/visibility cleanup or general containment.

Cross-owner adoption: process/device/mapping teardown retires both original grants after the shared copy lifetime was consumed, including the peer owned by another live process. The retained shared authoritative invocation supplies cleanup correlation only; both canonical original grant records, self/history counts, absence of independent pins/active submissions and pending interlocks must match. Each grant Close independently checks its own original factories/source and retains its own unknown response. No peer capability/root/mapping/Region ownership is transferred or released. Both exact closures retire the pair's storage reservations and payload correlation; the caller's ordinary process teardown releases its Region/charge, while a live peer keeps its Region/charge and regains existing CPU access. Device/mapping drain alone releases no OwnedMemory charge. Partial or lost Close observations retain reservations until exact original closure consumption; pure retry never repeats byte or Close effects. Accepted/publication/visibility pins remain outside this consumer.

Accepted-pair extension: retain both exact accepted leg records on the original invocation before callbacks and final publication. Optional IPlatformOriginalDmaCopyCompletionProvider explicitly makes completion observation a pure lookup of this original request/leg, allowing its own lost lookup to retain a separate invocation uncertainty rather than an independent unknown-effect pin. Raw completion replies precede validation/callbacks. Cleanup-only byte lifetime consumption may remove exactly those retained active records without fabricating completion, visibility or publication. Each leg must retain canonical self/history/source/cycle identity, have no independent submission pin, pending completion/page-fault user or retained resolved page-fault dependency. Missing/copied legs and history loss deny. Post-completion acquire now records its original visibility invocation before effect, raw before callbacks, issued-count/self history and existing original grant Close containment eligibility. Byte lifetime does not contain visibility: each original grant Close independently consumes its visibility uncertainty under its existing no-further-visibility-use contract. Trace notifications run outside owner gates after consumption and cannot strand the proven byte lifetime. Completed published pairs removed by ordinary visibility completion remain a separate retirement consumer.

Completed-pair retirement: both original completed leg records retain exact satisfied completion/visibility, original self/copy correlation and backend epoch. Cleanup consumes the explicit original byte lifetime producer rather than deriving it from Completed or missing active submissions. Incomplete/foreign completed projections, independent page-fault users/history/source drift deny before consumption. A legitimately already consumed original grant Close may account for exactly its one source revision transition and removed active visibility route; no fresh active permission is needed. Completed evidence remains intact, without a new quarantine/publication transition. Process/device/mapping drains also enumerate original retained payload grant references, including a locally closed/untracked leg whose peer/backing still needs cleanup. Both exact original closures consume the storage reservations; live peer Region/charge stays owned until its ordinary teardown. A completed lifetime is not queried or repinned on every retry; remaining original inventory and independent users/closure owners still govern peer retirement. No new native/API/package semantics.
