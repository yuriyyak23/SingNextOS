# ADR-041: Nested guest original lineage and quantitative cleanup

Accepted for implementation, 2026-10-11. Producing need: actual RuntimeKernel.MapGuestRegion could publish a nested mapping after native parent-factory history loss, and lost Map replies could leave a staged local mapping disconnected from its exact parent cleanup. Guest parent Map also bypassed existing quantitative mapping reservations. This extends ADR-040 software nesting through the existing original guest contracts; no machine change.

Native Map admission locks the root and immutable ancestor chain through the leaf. Canonical factories, issued histories, original parent grant and current ancestor readiness are checked with effect. Exact NoEffect is retained separately from closure and remains queryable after readiness changes. Guest Unmap requires original factory/history identity, not new active admission. History loss cannot establish containment.

SDK, provider and bridge reserve all ancestor sources before calls, retain original requests/raw before callbacks, and balance reservations in finally. Callbacks remain outside commit gates. SDK and bridge require captured revisions before final publication; copied or foreign raw observations cannot be replaced by a canonical response on retry. Only same-original pure query follows uncertainty. Returned-object compensation Unmap is forbidden.

For a lost Map reply, bridge cleanup projects only exact known closure or exact original no-effect to its captured local owner/handle. VirtualDomainAuthority retains the original cleanup association without publishing staged mapping permission. Kernel then consumes existing guest and parent finalizers before removing the local reservation. Completed closed lifetimes do not require a new active source query; independent faults, history loss and backing users stay pinned.

Actual child-backed guest parent mapping reserves PinnedMappedMemoryBytes before effect and binds the existing ResourceBudgetAuthority original mapping charge to the original bridge mapping owner. Existing mapping finalization consumes the charge once after exact closure. No new ledger or duplicate owner is introduced. Model-only mapping paths are unchanged by this charge adoption.

Runtime package 1.23.1 is adopted with Contracts 1.31.0; operationSchema1.4.0 and manifestContract1.3 unchanged. Evidence: [consumer record](../../artifacts/v6/iteration-20261011-nested-guest-lineage/report.md). Gates OFF, ISA NONE, no ProductionQualified. Durable cold recovery, all-fact-loss containment and independent artifact/backing histories remain open.
