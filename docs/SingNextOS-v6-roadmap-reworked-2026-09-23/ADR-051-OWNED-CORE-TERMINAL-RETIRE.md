# ADR-051: Original owned-core retire facts at managed terminal exit

Accepted for implementation, 2026-10-11. The actual compiled managed-array bounds consumer reaches the existing managed unhandled-exception ProcessExit ECALL (exit code 255). Its terminal result projection omits retire PC/sequence. Cycle count, current PC and Completed are insufficient to fabricate the missing original retire fact; the external provider must retain an independent observation from that invocation's actual core.

The allowed NonRTL owned observation source exposes an additive pure owner-thread reader of the core's existing last-retired bundle record. The source factory binds segment identity and entry address before CPU cycles. ExternalRuntime retains one Main binding, reads outside its execution lock, then validates binding identity, segment/entry, positive monotonic sequence and same-sequence PC agreement under its existing owner lock. Its terminal Dispose callback captures the last raw before source disposal. Missing/throwing/foreign/inconsistent terminal source denies receipted Start, even if an earlier boundary was observed. A terminal result already carrying retire facts must agree with the captured facts. No result is inferred from elapsed cycles.

This observation is neither permission nor containment authority. Original Start identity, admission and publication checks remain independent. Failed receipt publication cannot repeat CPU execution. Exact task-terminal backing closure remains separately available; independent users/history-loss pins are not removed by a retire snapshot. Completed means execution lifetime finished; exit 255 does not mean program success.

The standalone compiler consumes explicit SHA-validated metadata-only inputs and marks implicit array allocation/access exception transfer for the existing native EH linker/emitter. V1/raw/object behavior and machine legality remain independent. No core ISA, encoding, register state, memory model, pipeline, retire or firmware semantics change.

Actual adoption uses immutable ExternalRuntime 1.23.10; Contracts 1.34.0 and operation schema remain unchanged. Compiler-produced managed-array images are consumed by the SingNextOS RuntimeKernel caller, with quantitative backing/Region/budget checks. Verification and limitations belong to the [consumer record](../../artifacts/v6/iteration-20261011-managed-guest-allocation/report.md). Gates OFF; ProductionQualified false; Java-only skipped; ISA NONE. Whole-OS HybridCPU binary, durable cold recovery and general unknown/history-loss containment remain open.
