# ADR-040: Original external nested child factory and cleanup

Accepted for implementation, 2026-10-11. Producing need: RuntimeKernel.CreateNestedVirtualDomain has an existing local lineage owner and publication protocol, but the executable SDK/provider had no nested factory. This additive contract produces real external ChildRecord lifetimes and consumes their original closure through process teardown. It is bounded software provider admission, not machine VM nesting, stateful resume or physical qualification. ISA NONE.

The native optional IHybridCpuOriginalNestedChildRuntimeV1 retains a sealed request referencing the exact parent admission before possible Create effect. The existing original child Create request gains an explicit AllowNestedCreation flag, default false, and its original observation records the actual grant. A lease, equal receipt or old V1 Create alone does not grant nesting. Child execution authority remains independently subset checked; Lifecycle-only nested children can have ExternalChildAuthority.None without changing old V1 legality. MaximumDepth=64 bounds this external provider's admission work, not the ISA.

Native admission linearizes under the existing root gate and immutable ancestor gates, root to leaf. Canonical root/child inventories, original parent/root factories, issued history, parent grant, current source generation, readiness and authority/memory subset are checked with the effect. Nested children remain in the root's authoritative child inventory and retain their immediate original parent/factory. Parent Close checks nested users both before and after its irreversible work. A live descendant, unknown outcome or lost dependent history pins the parent. The existing native original Child Close proves exact terminal lifetime/no-further-use; Closed projections or absent children do not.

SDK and platform provider retain their own original requests and raw observations before source callbacks. They reserve ancestor interlocks before calls, execute callbacks outside commit gates, and balance reservations in finally. Only same-original pure resolution follows lost Create/Close replies. SDK final publication requires captured local revisions and fresh manifest; provider requires original root/parent factories and fresh source incarnation; the bridge retains its captured local lineage revisions and final authorization/publication checks. Unresolved Create cannot invoke again. Foreign/copy raw facts remain retained and pinned rather than being replaced with a returned-object compensation Close.

Unknown publication cleanup resolves the same native admission without publishing a new capability, then uses existing typed original Child Close. Exact NoEffect/NoFurtherAdmission is separate from accepted-child closure. Completed closures are retained by their existing owner and require no new active permission; independent event, guest, artifact and backing users remain governed by their own owners. Cleanup restores only the exact local fault revision created by this invocation and marks the child cleanup-only. Independent faults/history loss never regain active admission.

Actual Kernel quarantine retry must reconcile an invoked, unresolved optional original Close before trying another drain. This continuation is selected only while the original self/child owner is current, resolution is supported and no local closure receipt has been consumed. Legacy V1 and known closure paths retain their existing drain/lineage validation.

Implementation adopts immutable Contracts 1.31.0 and Runtime 1.23.0 through actual package references/assets; operationSchema 1.4.0 and manifestContract 1.3 are unchanged. Evidence: [bounded producer report](../../artifacts/v6/iteration-20261011-external-original-nested/report.md). Gates OFF; no ProductionQualified claim. Trusted durable storage/freshness/authenticated cold continuation, all-fact-loss recovery, incapable providers and independent history/users remain open.
