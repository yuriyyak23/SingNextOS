# Simulator Backend

## 1. Goal

Implement the product contracts first in HybridCPU-v2 ISE without baking simulator shortcuts into ABI.

Bad API:

```csharp
GetMemoryDevice(0)
```

Good API:

```csharp
IReadOnlyList<CxlBootCandidateEvidence> Discover(BootDiscoveryBudget budget)
```

Internal fixtures may store devices in arrays, but callers select by BootVolume/policy evidence.

## 2. Model layers

```text
HybridResetController
  -> PlatformPhysicalAddressMap
     -> ROM / RAM / MMIO / BootAperture

Stage0Runtime
  -> IPciConfigAccess ----------> ModelPciConfigSpace
  -> ICxlPrebootTransport ------> ModelCxlType3BootDevice
  -> ITemporaryBootAperture ----> ModelHdmRouter
  -> IProtectedBootStore -------> ModelProtectedNvram / ModelOtp
  -> IBootCrypto ---------------> deterministic software crypto
```

Each interface corresponds to a future hardware adapter.

## 3. `ModelCxlType3BootDevice`

Model fields:

```csharp
sealed class ModelCxlType3BootDevice
{
    PciLocation CurrentBdf;
    ulong? PciDsn;
    ulong? CxlSerial;
    byte[] Lsa;
    byte[] PersistentCapacity;
    CxlModelCapabilities Capabilities;
    ModelHdmDecoderBank Decoders;
    CxlBootFaultProfile Faults;
    Guid PhysicalFixtureId; // test-only, never exported as semantic boot ID
}
```

PersistentCapacity is initialized from HBV fixture images generated by shared tooling.

## 4. Modeled PCI/CXL progression

### Phase semantic model

Discovery can initially return candidate records directly. This validates identity/policy/failure semantics fast.

### Modeled PCI config

Add config-space hierarchy, bridge traversal, Type-3 class/capabilities, DSN, BAR/MMIO routing.

### Modeled mailbox

Implement abstract Identify, partition info, GET_LSA with real-ish payload bounds and injected completion/error/timeout.

### Modeled HDM

Make CPU reads to `FirmwareCxlBootAperture` succeed only when all required modeled decoder hops route to the target persistent range.

This progression avoids blocking architecture work on full CXL register emulation while ensuring final model exercises the same boundaries.

## 5. Deterministic scheduling

Boot tests must not depend on wall clock. `Deadline` is expressed in deterministic platform ticks/operation budget in ISE. Fault injector can specify:

```text
fail config read #N
mailbox timeout after K cycles
remove device after M persistent reads
corrupt byte at persistent offset
fail decoder hop H commit
reorder enumeration permutation P
warm reset preserving decoder state
```

Same seed + fixture produces same boot trace.

## 6. Boot ROM representation

Early implementation may represent ROM firmware as a host C# `Stage0Runtime` for contract tests, but Phase 2 exit requires a ROM byte-image path fetched/executed by HybridCPU instruction frontend for at least a minimal boot sequence. Host-side model remains a golden/reference oracle.

Do not claim “reset boots ROM” while harness still jumps directly to a C# callback.

## 7. Physical address map

Reference simulator map includes:

```text
SystemRam
FirmwareCxlBootAperture (256 MiB reserved)
MMIO/config windows
BootScratch
ROM at 0x00000000FFFC0000..0xFFFFFFFF
```

Exact non-ROM addresses can be configured by `ModelPlatformProfile`; BootInfo enumerates them.

## 8. Protected storage model

`ModelProtectedNvram` uses two copies + sequence + integrity tag. Tests can inject torn writes. `ModelOtpFuses` refuses changes after lock. This models semantics, not hardware strength.

Required test features:

- monotonic rollback floor;
- policy generation rollback rejection;
- key revocation;
- production lock vs development mode;
- boot attempt updates surviving simulated power loss.

## 9. Crypto fixtures

Use deterministic test keys checked into test data only, never production keys. Shared manifest tool creates:

- valid signatures;
- wrong key;
- revoked key;
- altered signed field;
- component hash mismatch;
- unknown algorithm/version.

## 10. Trace schema

Boot trace is evidence for tests:

```text
Reset(reason)
RomEntry(pc)
PolicyLoaded(generation)
CandidateDiscovered(evidenceDigest)
LocatorRead(result)
ApertureMapped(mappingGeneration)
HeaderAccepted(metadataSequence)
ManifestAccepted(imageId,generation,keyId)
ComponentVerified(type,hash)
Stage1Entry(address)
BootInfoSealed(digest)
KernelEntry(address)
OsFreshDiscoveryStarted
FirmwareApertureReleased
```

Trace handles/evidence are never authority.

## 11. Simulator-only early pieces

Explicitly simulator-only until replaced:

- direct semantic discovery backend;
- in-memory PCI topology;
- model CCI/mailbox timing;
- model HDM router;
- software OTP/NVRAM;
- deterministic fault injector;
- host-side Stage-0 oracle;
- simulated ROM measurement/proof signing.

Not simulator-only:

- data formats;
- selection rules;
- reset ABI;
- BootInfo ABI;
- authority transition;
- recovery/A-B semantics;
- security invariants.

## 12. Property tests

Useful invariant/property tests:

- permutation of physical enumeration does not change selected logical image;
- changing BDF cannot change BootVolume match;
- changing DSN only changes choice when policy has required/preferred selector;
- any single-bit manifest mutation either fails signature or signed hash binding;
- generation below floor never executes;
- no BootInfo CXL evidence handle can call provider operation;
- after reset, late completion from previous memory epoch cannot publish;
- partial HBV/header/NVRAM writes never select a state not present in one complete valid copy.
