## 4. Confirmed defect and remediation

- Critical authority leak: `ReleasePlan.ProviderEffectContained`, a caller-supplied Boolean DTO field, previously unlocked local authority release after provider loss. It is now explicitly evidence-only and ignored by `CanRelease`; current release requires `ProviderResourcesClosed` through the existing lifecycle owner.
- Caller-supplied `providerCancellationSupported` previously selected the cooperative-request transition label. The stored exact admission support now owns that decision; the compatibility parameter cannot upgrade it.
- Old host/conformance/adapter tests that treated a bare containment Boolean as proof were corrected: the claim fails and pins remain; only the locally executable provider-resource-close path releases.
- No global EffectEpoch, CPU-global state, new authority or containment ledger was introduced.

## 7. Fallback/FutureGated/HybridCPU exclusions

Fallback is cancellation-before-submit, otherwise drain/complete/resource-close or quarantine/reconciliation. Bounded preemption, checkpoint/drain guarantees and provider-contour containment need an exact provider generation-bound verifier plus executable close-vs-retire/late-effect enforcement; bypassing this would free Regions/budgets while late effects may still emerge.
